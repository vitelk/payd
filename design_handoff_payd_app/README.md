# Handoff: Payd app redesign (`front/`, paydprotocol.eth/app)

## Overview
Redesign of the six-tab Payd app — Tokens · $PAYD · Stats · Treasury · Launch · Docs — per `docs/DESIGN_BRIEF_APP.md` and the follow-up Tokens brief. Three things change: the **Launch** form gets a short default path (token, payout mode, basket) with everything else behind a "Set for you — change any of it" list, in both the one-transaction and three-signature shapes; the **Tokens** index becomes a card grid, newest first, with "Launch a token" as the first cell and the six-column table behind a Cards/Table toggle; and the **$PAYD** page gets a status sentence beside the name plus a collect card in the first viewport. Every ugly state named in the brief has a designed answer.

## About the design files
The `.dc.html` files in this bundle are **design references written in HTML** — prototypes showing the intended look and behaviour, not code to copy. The task is to recreate them in the existing app: **Vite + TypeScript + viem, plain CSS in `front/index.html`, no framework, no dependency, one entry point, one bundle.** Views keep rendering into their own host element; `route.ts` and the set of views are untouched. Inline styles in the prototypes map onto classes in `front/index.html`'s existing grammar (`.card`, `.k`, `.v`, `.note`, `.segs`, `.pill`, `.rule`, `.panel`, `.stepcard`, `.mk .box`, `.lp .lpt`); the prototypes already use the same CSS variable names.

## Fidelity
**High-fidelity** for layout, spacing, type, colour, states and copy. Two caveats:
- **Figures are not designed.** Every on-chain number is `—`, and the four figures the index does not read today are `{{…}}` placeholders (see "Reads and placeholders"). Do not invent any number.
- Rows other than PAYD (VOLT, MESA, KIRN, ORBIT, PALLAS, DRIFT, SOL8) and the stock allowlist come from `front/src/mock.ts`'s fixture; they are for `?mock`, not content.

## Shell (all views)
Unchanged structure: `.top` band (lockup · tabs · grow · Collect everything · Connect), hairline, `.frame` grid `19rem minmax(0,1fr)` with the rail, `.view`, footer. Changes:
- **Connect menu** gains a second part: the wallet rows (one per EIP-6963 announcement when there are several; "Disconnect" when connected), a hairline, then the "or look at an address 0x…" field. The header's `#peek` form moves here; `?address=` still fills it. Header holds one control on a phone.
- **Connect button** carries a 6 px dot: `--ok` on chain, `--bad` on the wrong network; label becomes `0x8d21…44af · wrong network` in that state.
- **Notice strip** (wrong network only) directly under the hairline: `--surface`, 6 px `--bad` dot, one sentence ("Your wallet is on another network. Everything here still reads; nothing can be signed until it is on Robinhood Chain."), and a `--ok` button "Switch to Robinhood Chain" → `ensureChain`. Every sign button on the page shows the same words meanwhile.
- **Collect everything** shows on every view but Tokens (Tokens has the position card instead), only when connected; badge counts launches ("3 held"), never ether.
- Phone (≤ 900 px): tabs become the fixed bottom bar (44 px min height, .625rem labels, selected = `--raised` background); the one primary action of the view (Collect now on $PAYD, the Launch CTA) pins above it as a full-width 13 px-radius button; the rail becomes the sheet the token chip opens (26 px top radius, veil `rgba(14,13,10,.55)`).

## Launch view
Same form in both shapes; only the step rail and the button change. Order top-down, left column (`flex: 1 1 24rem`):
1. **The token** — Name (placeholder "Payd Protocol"), Ticker (uppercase), 44 px inputs on `--bg`, 8 px radius, focus = inset `--edge` ring. Hint "written into it for good".
2. **How holders are paid — the payout mode** — five pressable cards (`auto-fit, minmax(13rem,1fr)`), each name + one line: Distribution (tag "default") · Tontine · Backing · Lottery · Portfolio (copy in the prototype, from the site brief). Selected = `--raised` + lime ring, name in `--ok`. Tontine reveals burnt % / locked-as-liquidity % (off or ≥ 5 %, ≤ 50 % together, snapped via `snapLeg`); Lottery reveals the pot % (5–50, `snapPot`). Only modes `factoryMode` answers non-zero for are shown.
3. **The basket** — allowlist as pressable chips (ticker + pool tier), selected = `--raised` + ring; picking re-evens the split (`spread`), shown as the same weight chips the $PAYD page uses; "Edit the weights" reveals per-stock number inputs and becomes "Even the split". Right-side status: "3 picked · 100.00 %" in `--ok`, or "one more at least" / "8 at most" in `--dim`.
4. **Set for you — change any of it** — a list of rows (44 px, hairline between): label `--mut` · value mono · "change"/"close". Rows and defaults: Holders' share 70 % (range 50–90 + number) · Epoch length 30 minutes (30–1440 step 30, "48 buys a day") · Launch currency native ETH (select, quotes from `quotelist`) · Your creator tax 3 % (0–10 step .25) · Your first buy none (ETH, native-ETH launches only) · Logo none (text, ipfs:// or https://) · Links your Payd page (website / X / Telegram) · Intended token any you deploy (text). Each opens inline with its field and today's note. Same element ids as today (`mk-rewards`, `mk-epoch`, `mk-quote`, `mk-tax`, `mk-buy`, `mk-logo`, `mk-site/x/tg`, `mk-intended`) so `create.ts` reads them unchanged.

Right column (`flex: 1 1 18rem`, sticky top 1rem; static on phone): "What a trade will pay" bar + legend (holders `--ok`, creator `--mut` "the rest", platform `--dim` "— (read from the registry, ≤ 15 %)") · checks list (✓ in `--ok`, · in `--dim`) · the CTA (48 px, 10 px radius) · one note.

Shapes:
- **One transaction** (`oneShot`): a single wide step card with lime ring — "01 · you, once — Create the payout, launch on Pons and point the fees at it" and the three calls in mono. CTA "Create, launch and bind — one signature"; disabled label "Name the token" / "Fix the basket". Note: "One transaction. Either all three land or none of them do — and if none do, no launch fee is spent."
- **Three signatures**: three step cards (01 you · 02 you · 03 anyone), current = ring + `--ok` tag, later = opacity .55, done = tag "01 · done". Stage 1 CTA "Prepare the payout"; on success the form folds to a one-line "01 · done — Payout prepared at 0x… · reopen · prepare another" and stage 2 shows a summary card (name · ticker, creator wallet = your payout contract, pair token, tax) with the CTA "Launch on Pons" and the **handoff table** folded under it ("Launching on Pons's own site instead? — every value, ready to copy"; creator wallet row in `--ok` 600). Stage 3: "The token to bind" field, CTA "Bind", note on what bind compares. `?mine=` / `localStorage` adoption as today.
- No wallet: CTA "Connect a wallet" opens the Connect menu; nothing on the page needs a wallet until signing. Wrong network: CTA "Switch to Robinhood Chain". Two extensions: the probe for atomic batching waits until one is chosen (as today's `probeOneShot`).

## Reads and placeholders (Tokens cards)
New reads, all in the same multicall tick as the six the index already makes: `Token.logo()` (1/card) · `Distributor.totalDistributed(stock)` (≤ 8/card, the headline) · `totalFunded(stock)` (optional) · `metrics.ts` pricing (shared) · `VaultCreated` block → timestamp (age, Newest sort; cached) · claimable for the viewer (artifact per held launch). Cards paint from round one and fill the headline from round two.
Placeholders: `{{paid_usd}}` Σ totalDistributed × price · `{{owed_usd}}` viewer's claimable, priced · `{{rewards_pct}}` economics().rewardsOfVolumeBps (read today) · `{{age}}` time since VaultCreated. No market cap, volume, holder count or price anywhere.
